# Backblaze B2 destination

put.gd uploads to Backblaze B2 through B2's native API (b2api v3), as its own storage
service, `backblaze-b2` (#282). B2's S3-compatible API can't be used: it has no
conditional writes ([S3-compatible services](s3.md#s3-compatible-services)).

## Setting it up

1. In the Backblaze web console, create the bucket. For links that never expire,
   make it **public** (allPublic). That needs payment history on the account; B2
   otherwise answers `no_payment_history`. For private files, leave it **private**
   and choose links that expire.
2. Create an **application key** for that bucket with `listBuckets`, `listFiles`,
   `readFiles`, `writeFiles` and `deleteFiles`, plus `shareFiles` for private-bucket
   links. A key restricted to the bucket is recommended. The master key also works
   with the native API, but it can do everything on the account.
3. In put.gd, **Destinations → Add destination → Backblaze B2**. Enter the bucket and
   an optional folder, choose who can open files, then enter the **Application key ID**
   and **Application key**. **Store credentials** saves them in the system keychain (or
   for this session only), as for S3.
4. **Test connection**. It authorizes the key and reports missing capabilities or a
   key restricted to another bucket. It then uploads a synthetic text file, fetches it
   through the same kind of link put.gd will hand out, removes exactly that file
   version, and starts and cancels a large file. A private bucket set to public links
   fails with `b2_bucket_private`, which says what to change.

## Settings

| Field | Meaning |
| --- | --- |
| `bucket` | Existing bucket name: 6–63 letters, digits or hyphens, not starting with `b2-`. |
| `objectPrefix` | Optional folder in the bucket, at most 900 bytes; a `/` is added when missing. |
| `linkMode` | `public` (allPublic bucket, links never expire) or `authorized` (private bucket, links expire). |
| `linkValidityDays` | 1–7 (B2's maximum is a week); authorized links only. |
| `publicUrlBase` | Optional HTTPS link domain, public links only. `null` uses `https://fNNN.backblazeb2.com/file/<bucket>/<name>`. |
| `apiUrl` | `https://api.backblazeb2.com`; tests point it at the loopback fixture. Not shown in Settings. |
| `connectTimeoutMs`, `requestTimeoutMs` | Per-request deadlines: 1–120 s, and 1 s–1 h (default 10 s and 600 s). |

Credentials use the S3 credential store: the key ID as the access key and the
application key as the secret. Configuration holds only the keychain reference.

## How uploads stay safe

B2 has no conditional create, and uploading an existing name adds a new version that
the name then serves. put.gd still never uploads over a visible file:

- The name check lists the name's versions. The name is taken when its newest
  version is an upload rather than a hide marker. The version IDs become the
  upload's baseline.
- After the upload, put.gd lists the versions again. A version that is neither its
  own nor in the baseline means someone uploaded the same name meanwhile. put.gd then
  deletes its own version by ID and reports a collision, so the next name is chosen,
  as with S3's 412. Neither link ever shows the other file.
- An explicit overwrite policy is refused for B2: there's no way to replace a file
  only if it is still the one put.gd checked.

The receipt records the exact file ID, SHA-256, size and publication identity.
History deletion removes exactly that file version (`b2_delete_file_version`) and never
adds a hide marker. If the version was the newest, the name then shows what came
before it: nothing visible, or an older version that was hidden before the upload.

Files over 64 MiB upload as B2 large files: `b2_start_large_file`, 16 MiB parts
(larger when 10,000 parts would not hold the file), each with its SHA-1, then
`b2_finish_large_file`.
- **Before the first part,** the large file is journaled on the history item as the
  upload's `uploadId`.
- **Retry** lists the stored parts and sends only those missing or different.
- **Cancel, a failed part and artifact cleanup** (after
  `retention.failedArtifactDays`, #146) call `b2_cancel_large_file`, so no parts keep
  using storage.
- **A finish whose reply was lost** is confirmed with `b2_get_file_info`.

## The B2 worker

All B2 HTTP runs in `putgd-b2-worker`, one process per request. The resident links no
network code for B2.

- **Request.** The resident starts the worker with `--stdio` and writes one JSON
  request, which includes the application key. The key never appears in argv, the
  environment or logs.
- **Messages back.** The worker writes newline JSON: upload progress, checkpoints (it
  waits for the resident's durable acknowledgement before relying on what it
  journaled), and one final result.
- **Cancellation.** A `{"cancel":true}` line, or a closed stdin, cancels.
- **Stuck worker.** A worker that stays silent for several request deadlines is
  stopped, and the outcome is treated as unknown.
- **Diagnostics.** The worker's stderr is read and discarded.

Qt Network sends a request again by itself when the connection closes before the
reply. The worker therefore sends every body (uploads, parts, API calls) from a device
that can be read only once. Qt then reports an error instead of replaying, and the
worker reconciles. A lost upload reply is recovered by finding the version with the
upload's publication identity. A lost deletion is checked by file ID before anything
is sent again.

## Links

- **Public buckets:** `https://fNNN.backblazeb2.com/file/<bucket>/<name>`, or the
  link domain plus the name. These never expire.
- **Private buckets:** the same URL plus `?Authorization=<token>`. The token comes from
  `b2_get_download_authorization` with the file's exact name as its prefix and lasts
  `linkValidityDays`. The receipt records `linkExpiresAt`. Without the token, B2
  answers 401. When the link expires, the file stays in the bucket until it is
  deleted from History. Refreshing an expired link from History is not supported yet.

## Limits

- Files up to 10 TB, names up to 1,024 bytes including the folder, parts of 5 MB to
  5 GB, at most 10,000 parts.
- One large file sends its parts one at a time. Borrowed parallel lanes (#174) are
  S3-only for now.
- A name with more than 100 versions is refused as inconclusive. Choose another
  folder or name.
