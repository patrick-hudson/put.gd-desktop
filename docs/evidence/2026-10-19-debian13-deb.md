# Debian 13 release DEB (issue #85) — 2026-10-19

Since #75 every package ships screen recording. Each DEB therefore depends on
the FFmpeg it was built against: `libavcodec60` for the Ubuntu 24.04 DEB and
`libavcodec62` for Ubuntu 26.04. Debian 13 ships `libavcodec61`, so no release
DEB installed there. Pull request #100 takes the issue's first option. It adds
a `debian13` target to the package matrix, built in a pinned `debian:13`
container against Debian's own Qt, LayerShellQt and FFmpeg. Collection, the
release bundle and the nightly and release publication inventories now require
`putgd-VERSION-debian13-x86_64.deb`. This record covers the CI build and audit,
the unchanged Ubuntu and Fedora packages, and the install, recording and
uninstall run on the physical Debian 13 Plasma Wayland desktop.

### Recording

The driver (`deb_record.py`, adapted from the AppImage campaign's `ar_record.py`;
see [that record](2026-10-19-appimage-recording-wayland.md) for the method) ran
on the workstation through `tools/lab/physical.py`:

- **Resident.** `/usr/bin/putgd --background` in the real session, with private
  `XDG_*` directories under `~/putgd-lab/d13` and no `QT_QPA_PLATFORM`.
- **Destination.** Every action used the local destination. The archive was
  under `~/putgd-lab/d13/archive`, and the payloads were the synthetic test
  patterns.
- **Input and frames.** Input came from the host's uinput agent and frames from
  the d69 wall tile.

Each set recorded 8 clips: region and whole monitor in MP4, WebM, GIF and WebP.

- **Region MP4.** The area was dragged in the helper's KDE layer-shell selector.
  The clip got system audio, Pause, Resume, Stop, a 0.5–4.5 s trim with a timed
  blur, preview, Save copy and Upload.
- **Other region clips.** These completed the selector with `recording.select`.
- **Monitor MP4.** This got the same full flow.
- **Every clip.** Each clip was saved as a copy, scored and uploaded. The upload
  operation then reached `completed`, with the file in the archive.

The installed helper scored MP4, WebM and GIF clips itself with
`putgd-record --motion CLIP 8`, because it links Debian's FFmpeg. Animated WebP
has no FFmpeg decoder, so WebP clips were scored with Pillow 12.1.1 on k72 by
the same measure (`webp_motion.py`).

### i915 (issue #89)

`journalctl -k` for the boot shows one GPU hang. It happened during the moving
set, at 06:44:12Z:

```
i915 0000:00:02.0: [drm] Resetting rcs0 for preemption time out
i915 0000:00:02.0: [drm] kwin_wayland[1043] context reset due to GPU hang
i915 0000:00:02.0: [drm] GPU HANG: ecode 9:1:85dffffb, in kwin_wayland [1043]
```

It was the only hang of this boot (KWin has run since 2026-10-17). It came in
KWin's own context while the monitor GIF exported on the CPU. Live
`vah264lpenc` recording had stopped at 06:43:56Z, and the fullscreen
`waylandsink` pattern was still scrolling. KWin recovered; the session, the
recording helper and every later step continued normally. k72's hang in #89 was
during live `vah264lpenc` encoding.

### Uninstall

`apt-get purge -y putgd` at 06:49:47Z removed only `putgd`. Afterwards:

- `dpkg-query` no longer knows the package.
- None of the 117 paths `dpkg -L` had listed remain, apart from shared non-empty
  directories.
- There is no `/usr/share/putgd`, `/usr/share/doc/putgd`, private library
  directory, `/usr/bin/putgd*` or `putgd*.desktop`.
- There is no `~/.config/putgd`, `~/.local/share/putgd`, `~/.cache/putgd` or
  `~/.local/state/putgd`. The runs used private directories, so they never
  created these.

`~/putgd-lab/d13` (private run directories, the synthetic archive and the DEB
copy) and the input agent's unit and socket were removed. The only process the
lock tool listed outside the session was another session's memory collector.
