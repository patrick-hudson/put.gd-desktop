## Checksum format coverage correction

The earlier sweep omitted flat JSON maps (`sha256.json`, `SHA256.json`, `files.sha256.json`, `checksums.json` and other path-map names) and alternate text names such as `EVIDENCE-SHA256SUMS`, `*.sha256` and prefixed SHA256SUMS inventories. The [format audit](checksum-format-audit.json) lists discovered current indexes, verified available members, unavailable entries and preserved historical snapshots. Recorded historical source/package identities and hash observations embedded in logs are not current publication indexes. Unavailable private or omitted files are not manufactured to make an inventory pass.

The six current phase-B cohort indexes, dependent completion manifests and combined index were refreshed in dependency order. Historical `followup-*` snapshots remain unchanged. The original cohorts relocated lifecycle records into `lifecycle/`; the verifier reconstructs only their file namespace in a temporary directory and calls the unchanged production `overlay_cleanup._evidence` validator. This checks the published byte chain, not a new guest run, original attestation or cleanup action. Other current publication indexes affected by redaction were refreshed too; entries for unavailable files keep their recorded values and are counted separately.

A file with a conventional index name (`SHA256SUMS`, `*.sha256`, `sha256.json`, `checksums.json` and prefixed variants) must parse as an index. If it doesn't, the audit counts it as a mismatch rather than skipping it. The one empty index, from an interrupted run, is listed under `emptyIndexes`. The phase-B driver source inventory (`driver-source-sha256.json`) is read from its nested `files` map. Its repository paths are counted as unavailable, not as verified.

Run `PYTHONPATH=. python3 docs/evidence/2026-10-31-native-pass/lab/checksum_chain_checks.py --test` for stale-digest regression tests; omit `--test` for the current chain and format audit. The main publication checks validate this chain too.
