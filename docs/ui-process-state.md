# U11 C view state

`validateUiState` is QtCore-only. Version 1 accepts only `schemaVersion: 1` and optional `settings`, `history`, `activity` objects. It enforces the 8 MiB compact-JSON limit. State stays in resident RAM; this implementation writes no payload or state files.

Settings keys: `draft`, `numbers`, `profileEditors`, `baseRevision`, `observedRevision`, `dirty`, `conflict`, `initialProfile`, `profileIndex`, `section`, `advanced`, `geometry`, `setupJobs`, `provisionalProfile`.

- `draft` retains the versioned configuration structure with explicit shared field lists. S3 profile settings are classified explicitly: bucket, region, endpoint, objectPrefix, storageClass, aclMode, publicUrlBase, addressing, connectTimeoutMs, requestTimeoutMs, lowSpeedBytesPerSecond, lowSpeedTimeSeconds. Proton fields are limited to accountRootUid, folderUid, folderName, shareByDefault, linkExpirationDays, sharePasswordReference and requestTimeoutMs. Credential metadata is limited to mode/reference. Unknown providers/settings keys reject retention and keep the window open. A future provider must deliberately extend this policy.
- `numbers` retains raw strings for the declared limits/retention fields, including invalid/incomplete text and exact MiB formatting.
- `profileEditors` is aligned with destination order, so renaming an ID does not move its draft. Each editor retains id, label, credentialMode, reference, acl, addressing, s3 (known raw field strings), providerJson, and a Proton editor containing its account UID, folder choices/selection, share preference and raw expiry/timeout text. Optional `providers` contains separate S3/Proton settings, credential references and raw editors; nested editors cannot contain another provider map. Defaults initialize an unvisited service once. The active visible editor is captured before switching, saving or checkpointing. Only the selected provider enters the saved configuration; inactive provider drafts remain in resident RAM across helper recreation and the current helper's successful Save. Explicit Reload/Cancel replaces the entire draft. Raw provider JSON is accepted only as a classified flat S3 field object; unknown keys, nested values and secret fields reject retention. Remove/reorder moves all state for the entry together.
- `provisionalProfile` is empty or contains one classified profile/editor parked by first-launch Save locally. It stays outside the configuration, allowing a local-only Save without an incomplete destination. Add destination restores it; explicit discard/reload clears it. It follows the same provider and raw-editor allowlists.
- `setupJobs` contains accepted setupId/kind/profileId tuples while awaiting completion. Reopen sends only setup.inspect; no setup mutation is automatically replayed. An uncertain inspection retains its accepted ID and stops polling. A later explicit accepted setup action replaces the older tuple for that profile and kind. Save/setup requests awaiting acceptance reject final-close retention until a reply or client timeout resolves their state.
- Geometry is `[x,y,width,height]`. Base accepted and observed revisions are compared with the authoritative reopened snapshot, including invalid external-file changes.
- Credential entry controls are never traversed/exported. Unclassified state is replaced before export by a content-free `stateError` marker that the resident rejects. The actual draft remains in the UI. Masked inputs are associated with each destination entry and service in helper memory only. Switching restores only that selection's inputs. Store clears the current inputs; Cancel, Reload, ordinary close and shutdown clear all inputs, including parked/inactive entries. They never enter provider drafts or resident checkpoints.

History keys: `query`, `filters`, `selectedIds`, `deletionId`, `filtersExpanded`, `managementExpanded`, `receiptExpanded`, `geometry`. Query and raw filters use only the existing named history filters plus query limit/offset. Selection is restored by matching IDs after async page load; vanished IDs clear. The accepted deletion ID is inspected after reopening. A confirmation awaiting its acceptance ID rejects close retention; the unaccepted confirmation and acknowledgement are not serialized or replayed. No history rows, details, links or preview pixels are retained in state.

Activity keys: `selectedId`, `selectedItemId`, `collapsedIds`, `geometry`. The list is fetched again; selected operation/item and expanded/collapsed states match IDs. No operation bodies or payloads enter state.

Helper cache: `UiSession` holds authoritative settings/build/diagnostic JSON and readiness. It coalesces invalidations; save/reload update the cache before callbacks and publish accepted/status signals afterward. Mutations use one client request and are never retried automatically. Edits typed while a save reply is pending keep their raw values and become a new unsaved draft based on that accepted revision. A single helper-owned `QThreadPool` worker handles bounded selected previews; final helper teardown drains it. All provider, credential store, database and resident service owners remain outside production views.

Cancel and Reload keep their current draft dirty and non-checkpointable until the resident reply arrives. Editing is disabled during that bounded request. Success replaces the draft with authoritative settings; failure retains the controls and conflict state.
