# U11 C view state

`validateUiState` is QtCore-only. Version 1 accepts only `schemaVersion: 1` and optional `settings`, `history`, legacy `activity`, and `main` objects. The redesign keeps legacy activity checkpoints readable, but opens History/Activity/Settings in one main window. It enforces the 8 MiB compact-JSON limit. State stays in resident RAM; this implementation writes no payload or state files.

The state also carries a derived, read-only `appearance` object: `theme` (the setting), `desktop` (`dark`, `light` or null), `desktopSource`, the resolved `scheme` and its `tokens` (name to `#rrggbb`). `ui.viewState` returns it unchanged; see [appearance](appearance.md).

Settings keys: `draft`, `numbers`, `profileEditors`, `baseRevision`, `observedRevision`, `dirty`, `conflict`, `initialProfile`, `profileIndex`, `section`, `advanced`, `geometry`, `setupJobs`, `provisionalProfile`, and the optional derived `captureRouting`.

- `captureRouting` presents Settings → Capture as shown: `default` (Default capture output) and one entry per capture action (region, window, desktop, clipboard, edit). Each has `profileId` (empty for no destination), the displayed `destination` and `sharing` texts, `publicationMode` (default/share/private), `effectivePublicationMode` (share/private, with "Use destination default" resolved for the selected destination; empty without an upload), the `status` line, and `destinationEnabled`/`sharingEnabled`; actions add `inherited` (Use default). An inherited action keeps its card visible with both controls disabled and showing the default's values. The resident returns only this projection and `section` through `ui.viewState` (MCP `get_view_state`), from the last accepted checkpoint; open windows checkpoint 250 ms after a change. Restoring ignores it and recomputes it from `draft`.

- `draft` retains the versioned configuration structure with explicit shared field lists. S3 profile settings are classified explicitly: bucket, region, endpoint, objectPrefix, storageClass, aclMode, publicUrlBase, addressing, connectTimeoutMs, requestTimeoutMs, lowSpeedBytesPerSecond, lowSpeedTimeSeconds. Proton fields are limited to accountRootUid, folderUid, folderName, shareByDefault, linkExpirationDays, sharePasswordReference and requestTimeoutMs. Credential metadata is limited to mode/reference. Unknown providers/settings keys reject retention and keep the window open. A future provider must deliberately extend this policy.
- `numbers` retains raw strings for the declared limits/retention fields, including invalid/incomplete text and exact display formatting (GiB/MiB/megapixels); config bytes/pixels are unchanged.
- `profileEditors` is aligned with destination order, so renaming an ID does not move its draft. Each editor retains id, label, credentialMode, reference, acl, addressing, s3 (known raw field strings), providerJson, and a Proton editor containing its account UID, optional account email, folder choices/selection, share preference and raw expiry/timeout text. Optional `providers` contains separate S3/Proton settings, credential references and raw editors; nested editors cannot contain another provider map. Defaults initialize an unvisited service once. The active visible editor is captured before switching, saving or checkpointing. Only the selected provider enters the saved configuration; inactive provider drafts remain in resident RAM across helper recreation and the current helper's successful autosave. Explicit Reload replaces the entire draft. Raw provider JSON is accepted only as a classified flat S3 field object; unknown keys, nested values and secret fields reject retention. Remove/reorder moves all state for the entry together.
- `provisionalProfile` is empty or contains one classified profile/editor parked when first-launch Capture disables all upload destinations. It stays outside the configuration, allowing local-only settings to save without an incomplete destination. Add destination restores it; explicit discard/reload clears it. It follows the same provider and raw-editor allowlists.
- `setupJobs` contains accepted setupId/kind/profileId tuples and an optional source revision while awaiting completion. Reopen sends only setup.inspect; no setup mutation is automatically replayed. An uncertain inspection retains its accepted ID and stops polling. A later explicit accepted setup action replaces the older tuple for that profile and kind. Save/setup requests awaiting acceptance reject final-close retention until a reply or client timeout resolves their state.
- Geometry is `[x,y,width,height]`. Base accepted and observed revisions are compared with the authoritative reopened snapshot, including invalid external-file changes.
- Credential entry controls are never traversed/exported. Unclassified state is replaced before export by a content-free `stateError` marker that the resident rejects. The actual draft remains in the UI. Masked inputs are associated with each destination entry and service in helper memory only. Switching restores only that selection's inputs. Store clears the current inputs; Reload, ordinary close and shutdown clear all inputs, including parked/inactive entries. They never enter provider drafts or resident checkpoints.

Main keys: `page` (integer 0–2 for History, Destinations, Settings), `geometry` (`[x,y,width,height]`). These UI preferences do not change the application configuration schema.

History keys: `query`, `filters`, `selectedIds`, `selectedItemId`, `deletionId`, `sharingId`, `gridMode`, `showCancelled`, `filtersExpanded`, `managementExpanded`, `receiptExpanded`, `geometry`. Query and raw filters use only the existing named history filters plus query limit/offset. Selection is restored by matching IDs after async page load; vanished IDs clear. The accepted deletion ID is inspected after reopening. A confirmation awaiting its acceptance ID rejects close retention; the unaccepted confirmation and acknowledgement are not serialized or replayed. No history rows, details, links or preview pixels are retained in state.

Activity keys: `selectedId`, `selectedItemId`, `collapsedIds`, `geometry`. The list is fetched again; selected operation/item and expanded/collapsed states match IDs. No operation bodies or payloads enter state.

Helper cache: `UiSession` holds authoritative settings/build/diagnostic JSON and readiness. It coalesces invalidations; save/reload update the cache before callbacks and publish accepted/status signals afterward. Mutations use one client request and are never retried automatically. Edits typed while a save reply is pending keep their raw values and are compared with the submitted document, so reverting a field queues the inverse change. After acceptance they become a new draft based on that revision. The submitted document and proposal serials stay in the helper only; an acknowledgement retires only the submitted serial, preserving a newer equal-valued parent proposal after a child override. Outstanding save requests still reject checkpoint retention. A single helper-owned `QThreadPool` worker handles bounded selected previews; final helper teardown drains it. All provider, credential store, database and resident service owners remain outside production views.

Reload keeps their current draft dirty and non-checkpointable until the resident reply arrives. Editing is disabled during that bounded request. Success replaces the draft with authoritative settings; failure retains the controls and conflict state.

The main window debounces finished field/toggle/selection changes by 400 ms, reuses revision-aware resident atomic validation/save, and flushes pending finished edits before final close or its explicit Quit command. Invalid fields stay local while independently valid fields may save. Stored credential hints are read separately through `setup.credentialHint`: only availability, storage mode, a four-character access-key ID prefix plus an ellipsis (short IDs fully masked), and secret/token presence are returned. This read never performs keychain IO or unlock; explicit Store/Unlock owns that interaction. Hints/placeholders are not part of view state or diagnostics. On explicit Show, `setup.revealCredentialSecret` returns the unlocked saved S3 secret from the resident cache after accepted/observed revision checks. It is displayed read-only and excluded from credential drafts, setup records, checkpoints and diagnostics. Hide, destination/provider changes, page hide, close, reload and credential clearing discard it; late replies cannot reveal it again. Typed replacement secrets retain the ordinary Show/Hide behavior.

Transient autosave failures retain the draft and block automatic replay. The optional boolean `settings.autosaveBlocked` preserves that state across helper recreation; Retry saving is an explicit action. Validation errors may still allow independent valid fields to persist. A close with finished edits waiting for an accepted setup job keeps the helper open until those edits can flush.

The redesign experiment also classifies the optional `draft.captureDefaults` object. Only scalar `destination`, `profileId` and `publicationMode` fields are allowed. Inherited action output is encoded in its existing destination field; credentials remain excluded from checkpoints.
