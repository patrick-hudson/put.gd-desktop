## Strategy

Remote item state is durable journal data, separate from the clearable History projection. Schema 5 backfills retained schema-4 history into `item_state` inside the existing migration transaction. Operation and recent reads hydrate this state; writes merge it instead of allowing stale operation snapshots to replace it. Deletion and replacement update both durable state and any surviving projection in one transaction. Remote metadata keys are replaced outright so successful retries cannot retain stale nested error/progress fields. For records cleared before upgrade, migration recovers known non-copyable outcomes from the retained deletion journal. Deletion targets are expanded once into a temporary indexed table, avoiding a repeated document scan per cleared item. Outcomes whose only record was already discarded cannot be reconstructed; no remote replay is introduced.

The full operation snapshot stays durable at every existing publication checkpoint. `checkpointOperation` limits ledger work to the changed IDs; acquisition and all-item transitions retain full passes. A changed-item transaction failure rolls back its operation snapshot and ledger together. This removes quadratic ledger SQL work, not the cost of serializing a full operation snapshot. Prepared-query reuse alone would not remove those repeated writes.

History notifications are metadata-only, queued to the session thread after successful commits and coalesced by a one-shot timer. No GUI, image or history cache is added to the resident. Cleanup closes retry admission on that same thread before creating its worker snapshot, and reopens admission before returning its completion response.

Graphical fixture verification compares all independently known synthetic pixels. Window/desktop checks cover the complete fixture paint area; dynamic decorations and the rest of the desktop are outside that oracle. Each attempt has immutable witnesses and checksums. Host mock tests establish harness behavior, not compositor acceptance.

## Native runner correction

The stricter region oracle exposed an existing QMP tablet normalization error on KDE. The installed full-screen helper returned 81×60 for the old requested 80×60 gesture because the final pointer position crossed Qt's half-pixel rounding boundary. Numeric protocol traces and authenticated helper results reproduce the defect without changing the app. Map against the inclusive 32768-step tablet range using the first tick at or above the requested pixel edge. Hold press/move phases for 100 ms and retain a mid-drag witness; keep the exact 80×60 oracle and original completion deadline. The first cancelled attempt's cause remains unconfirmed and its witnesses stay preserved. Verify the corrected runner on Cinnamon before resuming KDE acceptance; repeat current-version cross-desktop checks after the correction is committed. The frozen memory samplers are unchanged.

The runner clears prior drag witnesses before each attempt and cancels failed press/move/screenshot/endpoint-release gestures before releasing at the start point. Cleanup failures are recorded without replacing the primary error; new operation identities/states are observed even after a driver failure. Abort requests are not proof of cancellation or absence of side effects. Host failure-injection tests exercise the actual attempt handler and reject stale archived bytes; they do not establish graphical acceptance. Tablet contracts cover both truncated and nearest fixed-point quantization. Endpoint-release failure and failed outcome observation have explicit host subcases; a delivered event with a lost reply may already have completed a capture, so abort metadata is never treated as proof of rollback.
